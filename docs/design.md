# callmeter

`callmeter` is a Claude Code plugin that records every tool call a chat or sub-agent makes, with what it touched and what it cost, every model request, every sub-agent turn and every lifecycle event Claude Code hands a hook, into one local SQLite file, and answers questions from it: which files are read most and how large they were, which commands return the most text into a context, how context grows call by call, which call sequences repeat often enough to deserve one command of their own, and what each session, prompt, agent and effort level spent. It exists because the measured cost of agent-driven development is context blown up in long-running agents, and nothing recorded where the context went.

Decisions live in this file. A change lands here first, then in the code. How it is tested lives in [testing.md](testing.md).

## What it answers

1. Every call: the tool, its input, who made it (chat, sub-agent, agent type), under which prompt, at which effort and permission mode, how long it ran, whether it failed or was interrupted, and how many bytes the model received.
2. Files: read most, by count and by bytes delivered; their size on disk at read time; whole reads against ranged reads; the same file read again by the same agent; files written most, how much each write grew them, and the lines each edit added and removed.
3. Commands: which command shapes (`go test`, `git diff`, `make test`) deliver the most bytes into a context, per call and in total.
4. Context: the context size at every model request, per agent, so the call that pushed an agent from 40K to 400K has a name; the token split of every request (input, cache read, cache write at 5 minutes and at 1 hour, output) per model and agent type.
5. Sequences: runs of calls that repeat across agents (a search, then a read of the file it found, then a narrower read of the same file), ranked by how often they recur and what they cost, as candidates for one command or one script.
6. Sessions, prompts and agents: when each session started and ended and why, which model it ran, what each user prompt cost in calls, requests and tokens, and every turn of every sub-agent, a woken agent's later turns included.
7. Outcomes and coverage: commits made, test runners invoked, lines changed per file; and which transcripts on disk were never recorded, so a missing hook reads as a gap, never as a quiet week.

## The plugin

The repository is a one-plugin marketplace. `.claude-plugin/marketplace.json` at the root lists the plugin `callmeter`, sourced as a `git-subdir` of this repository at `plugins/callmeter`, ref `main`. Only what installs lives under `plugins/callmeter/`:

| Path | Holds |
| --- | --- |
| `.claude-plugin/plugin.json` | name, version (the one version the wrapper reads), description, author, keywords; no `hooks` or `skills` key, both sit at their default locations |
| `.claude-plugin/icon.svg` | the plugin's icon |
| `hooks/hooks.json` | the registration below |
| `libexec/callmeter` | the POSIX sh wrapper every hook and the skill run |
| `libexec/SHA256SUMS` | the release assets' sums, equal to a fresh reproducible build's |
| `skills/report/SKILL.md` | `/callmeter:report {topic} [flags]`, which runs the wrapper's `report` |
| `README.md`, `LICENSE` | what an installed plugin shows |

Everything else (`cmd/callmeter/`, `internal/`, `e2e/`, `scripts/`, `.github/workflows/`, `docs/`) builds, tests and releases the binary and never installs. There is no top-level `bin/`, and nothing is written to `${CLAUDE_PLUGIN_DATA}`.

The registration. Every entry is `{"type": "command", "command": "${CLAUDE_PLUGIN_ROOT}/libexec/callmeter", "args": ["hook"]}` plus its mode:

| Event | Matcher | Mode |
| --- | --- | --- |
| `PreToolUse` | `Bash` | `"async": true` |
| `PostToolUse`, `PostToolUseFailure`, `SubagentStart`, `SubagentStop` | `*` | `"async": true` |
| `PostToolBatch`, `Stop` | none | `"async": true` |
| `SessionStart` | none | sync, `"timeout": 60` |
| `SessionEnd`, `StopFailure` | none | sync, `"timeout": 2` |
| `Setup`, `UserPromptSubmit`, `UserPromptExpansion`, `InstructionsLoaded`, `PreCompact`, `PostCompact`, `PermissionRequest`, `Notification`, `PermissionDenied`, `TaskCreated`, `TaskCompleted` | none | `"async": true` |

Never registered: `WorktreeCreate`, `WorktreeRemove`, `MessageDisplay`, `FileChanged`, `ConfigChange`, `CwdChanged`, `DirectoryAdded`, `TeammateIdle`, `Elicitation`, `ElicitationResult`, `PreModelSwitch`, `PostModelSwitch`. A `WorktreeCreate` hook replaces Claude Code's own worktree creation, so registering it would change behaviour; `MessageDisplay` fires per streamed chunk; the rest carry nothing a report asks for or were never seen firing ([Evidence](#evidence)).

`SessionStart` is synchronous with a 60 s budget because its run is the one that may download the binary on first use; `SessionEnd` and `StopFailure` are synchronous with 2 s so they land before a headless process exits and cancels async hooks (a refused turn's `StopFailure` lands milliseconds before the `SessionEnd`). Every other entry is async: the hook fires on every call of every chat, and a synchronous hook would put a process start and a database write in front of each call.

## The wrapper

`plugins/callmeter/libexec/callmeter`, POSIX sh, mode 0755. It resolves a binary, then hands it its own arguments and untouched stdin. The hand-off is `exec` for the `$CALLMETER_BIN` override and for every run of an already installed cached binary: the cache check, the lock-wait loop finding the target, and the lock holder finding it installed after taking the lock. Only the run right after this run's own download and install, under `hook`, runs the binary as a child, so its non-zero exit or failed start still becomes a `binary exited {rc}` line in `missed.log`; under another subcommand that run is an `exec` too. Its root is the directory above the script's own, cut from the script's path by parameter expansion (a hook names the script by its path), so it works the same from a hook and from the skill; `{version}` is the first `version` string of `{root}/.claude-plugin/plugin.json`, read by a builtin `while read` loop over the file. The cache-hit path starts no process before its `exec`: the root, the version and the `.last-use` stamp come from shell builtins alone, because a headless exit kills a running hook within tens of milliseconds and every process started before the hand-off is a chance to lose the event.

Resolution order:

1. `$CALLMETER_BIN`, when set and executable: a development or test override that skips every step below.
2. `{CALLMETER_HOME}/bin/{version}/callmeter`, when executable: the cached binary of this plugin version.
3. A download of `${CALLMETER_RELEASE_BASE}/callmeter--v{version}/callmeter_{version}_{os}_{arch}` (`CALLMETER_RELEASE_BASE` defaults to `https://github.com/rezzminator/callmeter/releases/download`; os `darwin` or `linux` from `uname -s`, arch `amd64` or `arm64` from `uname -m`, anything else `unsupported platform`).

- Lock: `mkdir {CALLMETER_HOME}/bin/.lock-{version}` is the lock, removed by its holder on every exit path. A waiter polls for the cached file for up to 50 s, then fails with `lock wait timed out`; a lock older than 120 s is stale, removed once and retried. Eight hooks firing together on an empty cache download once. The holder sweeps only `{CALLMETER_HOME}/bin/.tmp-*` files older than 120 s, so another run's download in flight is never removed. The race is accepted: a holder suspended past 120 s can lose its lock to a waiter, and the two downloads then each verify against `SHA256SUMS` and land by atomic rename, so the cache path only ever holds a verified binary.
- Download: `curl` (connect 5 s, whole transfer 40 s) runs in the background under `wait`, which a trapped signal interrupts at once, where a foreground `curl` would hold the trap until it returned: a SIGTERM, SIGINT or SIGHUP mid-download kills `curl`, removes its temporary file and, under `hook`, appends the `killed by signal` line before the wrapper exits, inside Claude Code's grace between its SIGTERM and SIGKILL. A `curl` failure fails with `download failed`.
- Checksum: the download lands in a temporary file under `{CALLMETER_HOME}/bin/`, is summed with `shasum -a 256` or `sha256sum`, and must equal the line of `libexec/SHA256SUMS` naming its asset; a mismatch, no sum line or no sum tool fails. A verified file is made executable, renamed atomically into the cache path. Each version directory carries a last-use stamp `{CALLMETER_HOME}/bin/{version}/.last-use`, written at install and its mtime refreshed by every run served from that version's cache; a stamp write that fails never fails the run. After an install, and only then, a version directory other than the running one is removed when its stamp is at least 7 × 24 h old; a directory without a stamp ages by its own mtime. Only a directory whose name is a version string, `N.N.N` (each `N` one or more digits) with an optional `-` or `+` suffix of one or more of `[0-9A-Za-z.-]`, matched by builtin `case` patterns, is a version directory: any other entry under `bin/`, dot entries and a user's own directories when `CALLMETER_HOME` is `$HOME` among them, is never removed, however old.
- `missed.log`: any failure under `hook` exits 0 with nothing on stdout and appends one line `{unix seconds}\t{hook_event_name or unknown}\t{reason} (pid N)` to `{CALLMETER_HOME}/missed.log`, followed by `\t{session_id}` when the payload carries a session id made only of letters, digits, `.`, `_` and `-`. Every logged reason ends with ` (pid N)`, the writer's pid: the wrapper's `$$` or the binary's `os.Getpid()`. A line the wrapper cannot append (no home, a home it cannot create, a `missed.log` it cannot open or write) goes to stderr instead as `callmeter: missed: {event} {reason}`, followed by ` {session_id}` when there is one, so the unsuffixed reason survives in Claude Code's hook output; the exit stays 0. The binary in `hook` mode appends to the same file a line of the same layout, with reason `terminated by SIGTERM (pid N)`, `terminated by SIGINT (pid N)`, `terminated by SIGHUP (pid N)`, `terminated by store busy (pid N)`, `store unavailable: {class} (pid N)` or `panic (pid N)`, and the session id once its payload decoded with one in that alphabet (`AppendMissed`, `MissedSessionID`), so a killed, store-busy, store-less or panicked `SessionEnd` names its session. The binary turns each line into a `faults` row on its next run, hook or report, with `error` `{event}: {reason}` and the fourth field, when present, as its `session_id` (`parseMissedLine`): a reason starting `terminated by ` or `store unavailable: `, or the reason `panic` or one starting `panic (`, gives stage `terminated`, every other line stage `binary`. The ingest (`IngestMissed`) renames `missed.log` to `missed.log.ingest-{pid}` and takes each claim's flock, so parallel runs never ingest one file twice; its one transaction writes every line of the claim the run just made, a line identical to a stored fault included (two hooks of one session cancelled in one second and ingested by two runs are two faults), and from every other file a fault only beyond the identical rows (`ts`, `stage`, `session_id`, `tool_use_id`, `error`) the store already holds, so a claim whose run died after the commit is ingested again with no fault twice (an unparsed line is stamped at its file's last write for the same reason). Different writer pids keep same-second hooks distinct even through a pre-rename handle; re-ingesting identical bytes adds no duplicate. After the commit, still under the flock, each claim becomes `missed.log.done-{bytes read}-{pid}` and stays until 2 s after its last write: a line appended through a handle opened before the rename lands there, and the first ingest past the grace writes only the bytes past those read, then removes the file. A hook takes its signal handler's lock from just before that commit until its claims are moved. So a hook the wrapper could not serve, or a hook run killed or panicked before it recorded, is counted, never silent.
- The hook binary under a signal: `callmeter hook` handles SIGTERM, SIGINT and SIGHUP from before it reads stdin until it exits. A run's event is accounted for once its first write batch has committed or its first fault row has been written. A signal before that point appends one `terminated by SIG… (pid N)` line (event `unknown` until the payload decoded) and exits 0 with nothing on stdout; a signal after it exits 0 with no line; a signal while that batch or fault write holds the store's write lock (every write transaction takes it at its `BEGIN IMMEDIATE`, so it then finishes in milliseconds) waits for its outcome, then applies the same two rules. A signal while a write still waits on a busy store is decided at once and the wait given up: Claude Code (2.1.287, measured) SIGKILLs a cancelled async hook 1.47 to 1.52 s after its SIGTERM, so the `terminated by SIG… (pid N)` line must land inside that grace, never after a wait of up to 5 s. One run never leaves both a stored event row and a `terminated` line. Every statement's busy wait is bounded by the run's event (`storeWait`): half of the event's hook timeout less 400 ms, at most 5 s, from `hookTimeouts`, the one table of hook timeouts, which a test pins to `hooks.json` (`SessionEnd` and `StopFailure` 2 s, `SessionStart` 60 s, an async hook Claude Code's default 600 s; an undecoded event the strictest), so a `SessionEnd` gives up after 800 ms. A busy store before the event is accounted for appends one `terminated by store busy (pid N)` line, stops the run's store work and exits 0, so its sync hook is never killed mid-wait with nothing said; recovery then marks a `SessionEnd` so lost `lost`. A store that can take neither the event nor its fault for any other cause (no store opened, a schema version newer than the binary's, a full disk, a read-only or broken file, a refused insert), before the event is accounted for, appends one `store unavailable: {class} (pid N)` line the same way and stops the run's store work; the class is a fixed label, never the error's text (`StoreFailureClass`): `newer schema`, `full`, `readonly`, `io`, `corrupt`, `open` or `other`. A run already accounted for logs such a fault only. A panic in the signal handler is recovered there, logs its stack and exits 0 while holding the termination lock; it appends one `panic (pid N)` line only when the run is unaccounted and the handler has not successfully appended its own line. A signal ignored when the binary starts (`nohup`, a background job of a non-interactive shell) stays ignored and ends nothing. `callmeter report` and every other subcommand keep the default signal behaviour.
- Any failure under another subcommand prints `callmeter: binary unavailable: {reason}` on stderr and exits 1.

The binary's CLI:

- `callmeter hook`: one hook payload on stdin; exit 0 on every path; nothing on stdout.
- `callmeter report {topic} [--since D] [--project P] [--agent-type T] [--session S] [--limit N] [--json]` ([Reports](#reports)).
- `callmeter redact`: rewrites the rows already stored under [Privacy](#privacy), in one transaction, and prints the rows changed per column: `calls.input` (every stored input sanitized again by the current `SanitizeInput`, which leaves its own output unchanged: a `description`, `query` or `target` stored as text, an object or array under a kept field and every string of an `mcp__` tool's input become their `_bytes` count, a `url` loses its userinfo, query and fragment, a commit message or an `echo` or `printf` operand writing to a file becomes `'[cut]'`; a call whose input changed loses its `command_parts` rows, parsed again by the next report), `calls.error` (through `SanitizeError`), `events.detail` and the `parse` rows of `faults.error`; a second pass changes nothing; never run automatically, and every report counts the calls it would rewrite in one note ([Reports](#reports)); exit 0 when done or with no store, 1 on a store error, 2 on usage.
- `callmeter version`: `callmeter {version}`, set at build by `-ldflags "-X main.version={v}"`, default `dev`.
- `callmeter help`, `-h`, `--help`: usage on stdout, exit 0; no argument or an unknown subcommand: usage on stderr, exit 2.

Release assets are raw binaries `callmeter_{version}_{os}_{arch}` for linux/amd64, linux/arm64, darwin/amd64 and darwin/arm64 under the tag `callmeter--v{version}`, built with `CGO_ENABLED=0 go build -trimpath -buildvcs=false -ldflags "-s -w -buildid= -X main.version={v}"` on Go 1.27.1 exactly, so the committed `SHA256SUMS` reproduces from source.

## What the harness gives a hook

Measured on Claude Code 2.1.280 with a capture hook that logged every raw payload, and again on 2.1.286 as a plugin under `claude -p --plugin-dir`; see [Evidence](#evidence).

| Event | Fires | Carries what callmeter needs |
| --- | --- | --- |
| `PreToolUse` | once per tool call, before it runs | `tool_use_id`, `tool_input`, `cwd`: the directory the command starts in |
| `PostToolUse` | once per tool call that ran | `tool_use_id`, `tool_name`, full `tool_input`, the tool's own result object, `duration_ms`, `cwd` (it follows the shell's `cd`: for `cd /x/sub && grep …` started in `/x`, `PreToolUse` carries `/x` and `PostToolUse` `/x/sub`), `session_id`, `transcript_path`, `prompt_id`, `permission_mode`, `effort` (sonnet, not haiku); a sub-agent's call adds `agent_id` and `agent_type` |
| `PostToolUseFailure` | once per call that failed | the same, with `error` and `is_interrupt` in place of the result |
| `PostToolBatch` | once per model request, after all its calls | `tool_calls`: every call of that request, each with `tool_use_id` and `tool_response` as the exact text the model received (a string) |
| `SubagentStart` / `SubagentStop` | once per sub-agent turn: an agent woken again (an orchestrator waiting on its children, a `SendMessage`) starts and stops once per turn | `agent_id`, `agent_type`, `prompt_id`; the stop adds `agent_transcript_path`, `last_assistant_message`, `background_tasks`, `session_crons`, `stop_hook_active`, and fires 20-50 ms after the final message is stamped, before its line is flushed to the agent's transcript |
| `Stop` | once per turn of a chat | `transcript_path`, `last_assistant_message`, `background_tasks`, `session_crons`, `stop_hook_active` |
| `StopFailure` | a turn that ended in an API error instead of `Stop` | `error` (`model_not_found`, `max_output_tokens`), sometimes `effort` |
| `SessionStart` | once per process start, resume and compaction | `source` (`startup`, `resume`, `compact`); `model` only for `compact` |
| `SessionEnd` | once per process exit, when Claude Code runs it | `reason` |
| `UserPromptSubmit`, `UserPromptExpansion` | per user prompt, per slash-command expansion | `prompt` (measured, never stored), `command_name`, `command_source`, `expansion_type` |
| `InstructionsLoaded` | per instructions file loaded | `file_path`, `load_reason`, `memory_type` |
| `PreCompact`, `PostCompact` | around every compaction | `trigger` |
| `Setup` | `claude --init-only` | `trigger` |
| `PermissionRequest`, `PermissionDenied`, `Notification` | a permission prompt, an auto-mode denial, a notification | `tool_name` (stored in `events.tool_name` for both permission events), `tool_input`; the denial adds `tool_use_id`, kept in `detail` as an id so it joins its `calls` row; `notification_type` |
| `TaskCreated`, `TaskCompleted` | the task tools | `task_id` |

What no payload carries: the context size of a request and the model message id. Both live in the transcript, keyed by `tool_use_id`. The request is not on disk when `PreToolUse` fires, is usually on disk when `PostToolUse` fires, and was on disk in every check made 0.5 s later.

Three sizes exist for one Bash output, and only one is the cost:

| Size | Where | `seq 1 7000` |
| --- | --- | --- |
| Real | `tool_response.persistedOutputSize`, or the stdout length when nothing was persisted | 33,893 |
| The tool's result object | `PostToolUse` `tool_response.stdout`, cut at `BASH_MAX_OUTPUT_LENGTH` (default 30,000 chars) | 30,000 |
| Delivered to the model | `PostToolBatch` `tool_response` | 2,241: a `<persisted-output>` notice, the file path and a 2 KB preview |

Output under 30,000 chars is delivered whole; output over it is saved to `{session}/tool-results/*.txt` and delivered as the preview. The costly band is therefore just under the limit, and a later `Read` of a `tool-results/` file is the model going back for the rest.

A `PostToolUse` hook can replace a Bash result before the model sees it, with `hookSpecificOutput.updatedToolOutput`. `PostToolBatch` carries the text after that replacement, so the delivered size stays true when a filter is in play, and the gap between real and delivered bytes measures what a filter saved.

## The hooks

One command, `callmeter hook`, reached through the wrapper and registered on every event of [The plugin](#the-plugin)'s table. It is one command registered once per event: a duplicate registration is the same command appearing twice under one event.

- `PreToolUse` for Bash only, for its `cwd`, and its `tool_input` as a fill for a call whose `PostToolUse` is lost: the parser replays a command's own `cd` from the stored directory, so it must be the one the command started in, and only `PreToolUse` carries that. Everything a pre-call stat would give is in the result: `Write` and `Edit` return `originalFile` and a `structuredPatch`, so the size before and after and the lines added and removed come from the result; `Read` returns `startLine`, `numLines` and `totalLines`, and the file is stat'ed when the record is written.
- The hook never blocks and never fails a call: it exits 0 on every path and prints nothing on stdout. A failure to record goes to `{CALLMETER_HOME}/callmeter.log` with the session and `tool_use_id`, and is counted in the store's `faults` table, so a report can say "N calls were not recorded" instead of showing fewer calls; a store that cannot take that fault either gets a `store unavailable: {class} (pid N)` line in `missed.log` instead, counted on the next run that reaches it. A panic in the hook is recovered in `callmeter hook` itself: it exits 0 and prints the panic and its stack to stderr. Only a run whose event is not yet accounted for appends one `panic (pid N)` line to `missed.log` with the event and session id of the payload read so far (`unknown` and none when it named none), and logs the panic and its stack to `callmeter.log`; after accounting, `AccountedPanic` suppresses that run's missed line. The signal handler recovers independently under the same accounted rule, its own successful missed append suppressing a second line; it always logs its panic and stack. `callmeter report` recovers a panic, prints `callmeter: report panicked: …` and its stack to stderr, logs one report failure when its home resolves, and exits 1; usage stays exit 2. A `PostToolBatch` store-open or store-close failure is reported once per batch `tool_use_id`; an unaccounted run leaves one missed line, not one per call. A close failure after the batch committed leaves no missed line.
- It changes nothing a model sees: no hook output, no added context, no blocked call.
- A session records only from the moment Claude Code loaded the plugin's hooks; a session started before the plugin was installed or enabled records nothing until it starts again.

## Where each fact comes from

| Fact | Source |
| --- | --- |
| Tool, input, duration, agent, permission mode | `PostToolUse` / `PostToolUseFailure`; `calls.prompt_id` is the issuing prompt: `PreToolUse` or `PostToolBatch` writes it, `PostToolUse` / `PostToolUseFailure` only fills it |
| Effort | the payload's `effort.level`; absent payload effort follows the event and session-model rule in [Effort](#effort) |
| cwd | a Bash call's `PreToolUse`, the directory the command started in; `PostToolUse`'s, where the command left the shell, only fills a call whose `PreToolUse` was never recorded (either may land first: `PreToolUse` overwrites, `PostToolUse` fills only an empty `cwd`) |
| Real output size, persisted path | `PostToolUse` `tool_response`: Bash `persistedOutputSize`, else stdout bytes; Read `file.content` bytes; successful Edit, Write and Agent have NULL `bytes_real` (no separate real output). A failed call stores its error text's byte length; previously stored sizes keep their old value until a result hook overwrites them |
| Bytes delivered to the model; which calls shared one request; the tool, the sanitized input and file columns, and for a refusal the outcome label, of a call no earlier hook filled (only filling, never overwriting) | `PostToolBatch` |
| File size at read time | stat of `tool_input.file_path` when the record is written |
| File size before and after a write; lines added and removed | `Write` / `Edit` result: `originalFile`, the new content and `structuredPatch` |
| Commit sha and branch | `CommitFromText` scans a Bash `git … commit` call's stdout or, on failure, its error for a `[{branch} {sha}]` summary line; only sha and branch are stored, never the message |
| Test runner | the first Bash segment running `go test`, `pytest`, `npm test`, `vitest` or `cargo test`, after assignments and `env`, `timeout` or `nice` wrappers; `go -C DIR test` is a test run too (`TestRunnerOf`) |
| Model message id, model, stop reason and token split of the request | the transcript: the assistant message holding the call's `tool_use_id`, its model, stop reason and `usage` from the message's last entry. Read when `PostToolBatch` is recorded; a request not yet on disk is marked pending and filled at the next batch of the same chat or agent, or at the next `Stop`, `SubagentStop` or `SessionEnd`; a `Stop`, `SubagentStop` or `SessionEnd` also writes every request its transcripts hold, replies with no tool call included, the main chat's `Stop` once its transcript's last assistant entry ends the turn of the stop's `prompt_id` with no user entry of that turn after it (`ReadTurnRequests`, at most 3 s); a report run writes them for a quiet session ([Reports](#reports)) |
| Delivered size, failure, outcome label and real size of a call no result hook recorded | its transcript `tool_result` (`SettledCall`), only filling: delivered content bytes, failure and outcome; a failed call's text size, else `callmeter.RealBytes` of top-level `toolUseResult`. Successful Edit, Write and Agent keep NULL real size and settle once `failed` is set, even with no `toolUseResult`; other successful tools need that object to fill real size. `Stop` and `SessionEnd` settle unfinished calls; quiet-session recovery also settles calls rebuilt from `tool_use` in the same run. A timestamped call with only its batch size can gain real size; a ts-less batch row keeps its batch size alone. Recovery marks a call it cannot fill once with a transcript fault, and a later hook reopens it |
| A turn end whose `Stop` or `StopFailure` hook was lost | `SessionEnd`, and a report run for a quiet session, the one path when `SessionEnd` never ran ([Reports](#reports)): how the main transcript's last message ends the turn (`TranscriptTurnEnd`), when the session's latest prompt got neither a main-chat `Stop` nor `StopFailure` at or after the prompt, matching `prompt_id` when both carry one; a missing id retains the timestamp-only match. A final `<synthetic>` API-error entry is a `StopFailure` event; an answer with `stop_reason` `end_turn` or `stop_sequence` is a `Stop` event and a `turns` row under the same id, its `effort`, `permission_mode`, `last_assistant_message_bytes`, `background_tasks`, `session_crons` and `stop_hook_active` NULL (unknown); a turn waiting on a tool or a prompt, or interrupted, gets none. Each carries `detail` `{"from_transcript":true}` (`RecoverTurnEnd`); the hook's own `Stop` or `StopFailure`, when it lands later, replaces either kind, its `turns` row included (`DropRecoveredTurnEnd`, matched to that hook's prompt and no earlier than that prompt; a rebuilt NULL-prompt end in that span is replaced too) |
| A sub-agent turn end whose `SubagentStop` hook lost its event (store busy, a signal) | A report run for a quiet session ([Reports](#reports)): when an agent's latest turn has no stop and the agent's transcript, read in full, holds a request ending a turn (`stop_reason` set, not `tool_use`) at or after the turn's start, the earliest such end is that turn's `SubagentStop`; with no such end, the earliest qualifying task-notification in the main transcript at or after the start supplies the stop instead: an events row and a `turns` row under one id, dated at that turn end or task notice, never before the turn's start, its `effort`, `permission_mode`, `last_assistant_message_bytes`, `background_tasks`, `session_crons` and `stop_hook_active` NULL (unknown); the agent's turns are rebuilt so the turn closes at it, the agent's `stopped` keeps the latest, its `total_tokens` and `tool_uses` come from the transcript as the hook's latest stop writes them, its model only fills. It carries `detail` `{"from_transcript":true}` (`RecoverAgentStop`); the hook's own `SubagentStop`, when it lands later, replaces it, its `turns` row included (`DropRecoveredAgentStop`) |
| Sub-agent transcript | `{transcript_path without .jsonl}/subagents/agent-{agent_id}.jsonl` |
| Parent of a sub-agent | the `Agent` call's result `agentId`, joined to `SubagentStart`; missing parent and type also fill from `agent-{id}.meta.json` beside its transcript at `SubagentStart`, `SubagentStop` and every report-time recovery, live or quiet, preserving stored values |
| A sub-agent's totals | the agent's own transcript, read at every `SubagentStop` once its final message is on disk (up to 3 s, `agentSettle`, waiting for the stop's own `prompt_id`). `agents.total_tokens` sums input + cache read + cache write + output over every request of the agent; `tool_uses` counts its distinct `tool_use` blocks. The latest stop wins, hook-written or rebuilt by recovery, so woken agents include all turns. The `Agent` result fills neither total; it links the parent and supplies `resolvedModel`, else the transcript's last model fills `model`. An agent without any stop keeps NULL totals; a quiet open turn without an agent-transcript turn end closes at its earliest qualifying main-transcript task notice at or after its start, using the whole agent transcript's totals; with neither end nor notice it is marked once as unfillable. A finished background transcript with null `stop_reason` costs the stop its full 3 s wait before sums are read |
| Sub-agent turns | the stored `SubagentStart` and `SubagentStop` events of the agent ([The store](#the-store)) |
| Session start, end and model | the stored `SessionStart` and `SessionEnd` events and the session's main-chat requests; a report run for a quiet session whose latest run has no `SessionEnd` ([Reports](#reports)) |
| Host and time zone | the hook process: host name, and the zone name and UTC offset it computes (Claude Code leaves `TZ` unset) |
| Seat | the hook process's `CLAUDE_CONFIG_DIR` ([The store](#the-store), `seat_dir`) |
| Chat name, in reports | the session's own transcript under each seat it ran in: its last `customTitle`, else `aiTitle`, else `summary`, else the session id's first 8 characters |

## Where the store lives

The store is `{CALLMETER_HOME}/callmeter.db`, where `CALLMETER_HOME` is `${CALLMETER_HOME:-${XDG_STATE_HOME:-$HOME/.local/state}/callmeter}` (`XDG_STATE_HOME` counts only when absolute). Beside it: `callmeter.log` (JSON lines), `missed.log`, `archive.db` and the binary cache `bin/{version}/callmeter`. Under `go test`, resolving `CALLMETER_HOME` with the variable unset is an error, never the real home.

This deviates from Claude Code's plugin convention on purpose. The store lives at `CALLMETER_HOME`, never `${CLAUDE_PLUGIN_DATA}`, because plugin data is per seat (`{CLAUDE_CONFIG_DIR}/plugins/data/callmeter-{marketplace}`, observed on Claude Code 2.1.286) and pfm runs several seats whose calls belong in one store, and because the CLI and pfm must find the store without plugin env. One machine, one store: every seat's sessions land in the same file, told apart by `seat_dir`.

## The store

One SQLite file, its own: every call of every chat writes to it. WAL mode, `busy_timeout` 5 s against the concurrent async writers (a hook's own bound is tighter for a sync event, [The wrapper](#the-wrapper)), one short transaction per write batch of a hook run, each taking the write lock at its `BEGIN IMMEDIATE`, so a writer waits only there.

`PRAGMA user_version = 1`. A file at version 0 gets the whole schema in one `BEGIN IMMEDIATE` transaction; a file at version 1 opens without writing; a file at a higher version is refused with `newer than this callmeter`, never opened and misread. There is no migration code. An open retries a busy open until the busy timeout, because the first async hooks race to create the file and SQLite's switch to WAL takes no busy wait.

`ts`, `started`, `stopped`, `first_ts` and `last_ts` are integer Unix milliseconds, UTC. Hook rows use the run's clock; a result hook estimates `calls.ts` from its duration, requests use their transcript timestamp, and rebuilt rows use the transcript timestamps described below.

Indexes: `calls_session_agent_ts(session_id, agent_id, ts)`, `calls_ts(ts)`, `calls_file_path(file_path)`, `calls_prompt(prompt_id)`, `requests_session_agent_pending(session_id, agent_id, pending)`, `turns_session_ts(session_id, ts)`, `events_session_ts(session_id, ts)`, `events_event_ts(event, ts)`.

- `source` is `hook` on every row a hook writes; quiet-session recovery's rebuilt `calls` and `requests` carry `transcript` ([Reports](#reports)). Recovery also revisits a rebuilt successful call whose real output remains unknown (`callOpen`).
- `config_dir` is `$HOME/.claude`, the history home whose `projects/` holds the transcripts. `seat_dir` is the hook process's `CLAUDE_CONFIG_DIR`, the seat the chat ran under, made absolute and clean with symlinks NOT resolved; unset or empty, it is `$HOME/.claude`. Both are set on every row the hook writes that carries them, and a set value is never overwritten by a write that lacks it.
- `calls.error` never holds a failure's text: it is `Exit code N` when the text's first line is that, an outcome label for a call Claude Code never ran (`denied by a PreToolUse hook`, `denied by permission`, `rejected or interrupted by the user`, and `refused by Claude Code` for a refusal the harness wrapped in `<tool_use_error>`), else `error text not stored`; an auto-mode permission denial stores `denied by permission`. A failed call settled from its transcript's `tool_result` stores the same: its label, `Exit code N` or `error text not stored`, never NULL.
- The request key: `requests.request_id` is the model message id once the transcript shows it. Until then it is the provisional key `pending:{first tool_use_id of the batch}`, with `pending = 1`. When the id is later read from the transcript, the fill rewrites that request row to its real `request_id` and rewrites every `calls.request_id` that still carried the provisional key, in one transaction. `context_tokens` is `input_tokens + cache_read_tokens + cache_creation_tokens` from that message's `usage`; `cache_creation_5m_tokens` and `cache_creation_1h_tokens` are the split of `cache_creation_tokens` by cache TTL.
- A sub-agent's parent comes from the `Agent` or `Task` call whose result carries `agentId`: that agent is upserted into `agents` with the calling `tool_use_id` as `parent_tool_use_id`, together with the result's `resolvedModel`; the result never fills `total_tokens` or `tool_uses`. `SubagentStart` and `SubagentStop` also fill missing `parent_tool_use_id` and `agent_type` from `agent-{id}.meta.json` beside the agent transcript (`SubagentMeta`, `FillEmpty`); a payload type or stored parent wins, and absent or unreadable metadata is silently ignored by these hooks.
- `faults.stage` is one of `payload`, `store`, `transcript`, `parse`, `binary`, `terminated`, naming where the failure happened; `binary` rows come only from a wrapper line of `missed.log`, with the session the line names or none, `terminated` rows only from a line the hook binary itself wrote there (a signal, a busy or unavailable store, a panic). A fault that cannot itself be written to the store is logged; an unaccounted hook also leaves one `store unavailable: {class} (pid N)` or `terminated by store busy (pid N)` line in `missed.log`, while an accounted run leaves no additional line. A fault naming an event callmeter does not record names it `(name not stored, N bytes)`; a transcript timestamp that is not RFC 3339 is named by its message id and its byte length only.
- Every tool-call write is an upsert by its row's key, setting only the columns its event owns and leaving the rest untouched, because async hooks arrive in any order: a `PostToolBatch` can land before its `PostToolUse`.

### Identity and order

- `event_id` derives from the lowercase hex SHA-256 of the hook run's raw stdin. A delivery of the same bytes within 1 s (`RedeliveryWindow`) of a stored occurrence is that occurrence redelivered, the row holding its earliest delivery; further apart it is a new occurrence. The earliest occurrence holds the plain hash and every other one `{hash}:{its earliest ts}`, so the ids follow from the deliveries' ts, never their arrival order. So an agent woken twice in one prompt (identical `SubagentStart` bytes seconds apart) has two turns.
- The store is a function of the set of (payload, ts) pairs, never of their arrival order. `calls.ts` keeps the earliest start any of the call's hooks supplied (`KeepMin`, whatever the upsert's mode): `PostToolUse` / `PostToolUseFailure` estimates every tool's start as its hook time minus non-negative `duration_ms`, or its hook time when duration is absent or negative; `agents.started` keeps the minimum, `agents.stopped` the maximum, and the totals of the stop with the greatest `ts`; `agent_turns` and the derived `sessions` columns are recomputed from stored rows inside the write transaction.
- `agent_turns` for one agent: its `events` rows with event `SubagentStart` or `SubagentStop`, ordered by `(ts, event_id)`, walked once. A start opens a turn (an already open turn stays with `stopped` NULL); a stop closes the open turn; a stop with no open turn is a row with `started` NULL; `seq` counts from 1. A compaction's `SubagentStop` (empty `agent_type`, transcript missing) makes `events` and `turns` rows but no `agents` or `agent_turns` row.
- `sessions` derived columns: `start_source` is the `source` of the session's earliest `SessionStart` event; `end_reason` the `reason` of its latest `SessionEnd`, or `never` (`EndReasonNever`), set by quiet-session recovery when the session's latest run has no `SessionEnd`, or `lost` (`EndReasonLost`), set by it when that run's `SessionEnd` ran and was lost ([Reports](#reports)), each cleared by the session's next hook that recomputes these columns, and `never` also by any hook of the session dated after its `last_ts` (`TouchSession`), since the session runs again; `model` the `model` of its latest main-chat request (`agent_id` NULL) whose model is set, else of its latest `SessionStart` carrying one. `first_ts` is the minimum and `last_ts` the maximum over every run of the session; `cwd`, `seat_dir`, `config_dir`, `host`, `tz_name` and `tz_offset_minutes` each hold the value of the earliest run (smallest ts) that carried that column non-NULL, and on equal ts the smaller value wins, so the result is independent of arrival order; each column's `{column}_ts` holds the ts of the run that supplied its stored value, NULL while the value is NULL, and a run sets a column it carries when the stored value is NULL, when its ts is below that column's `_ts`, or when the ts is equal and its value smaller. `sessions.transcript_path` instead holds the newest run's non-empty main-transcript path, the larger path at equal ts, with that run's ts in `transcript_path_ts`; absent and empty paths never replace it. Recovery and the faults topic use `ResolveTranscript`: keep a path that exists, otherwise look for `{projects root}/*/{session_id}.jsonl` under the stored path's projects root, then the seat's, taking the first sorted match; `engine` is `claude`.

### Privacy

No prompt text, message text or file content is ever stored: each becomes `{name}_bytes`, its UTF-8 byte count. `last_assistant_message` is stored only as `last_assistant_message_bytes`, a prompt only as `prompt_bytes`.

- What is stored of a tool input: the sanitized input JSON keeps file paths and search patterns (`file_path`, `notebook_path`, `path`, `pattern`, `glob`) when their value is a string, every number, boolean and null (the `Read` range, a timeout), and the label fields (`subagent_type`, `model`, `skill`, `task_id`, `shell_id`, `url`, `output_mode`, `type`, `cell_id`, `cell_type`, `edit_mode`, `to`) up to 4096 bytes, a `url` cut before its first `?` or `#` and its `user:password@` userinfo cut from before the host, so its userinfo, query and fragment are never stored. The kept and label fields apply only to Claude Code's built-in tools: an `mcp__` tool's keys mean what its server says (a `to` may be a mail address), so every string of its input, a `path`, `url` or `to` included, is stored only as `{name}_bytes`, and only its numbers, booleans and null stay. A `description`, `query` or `target` is model-written free text, stored only as `description_bytes`, `query_bytes` or `target_bytes`. A `Bash` or `Monitor` `command` is kept with every heredoc body cut out at capture, the redirect line and closing delimiter kept, and of an unquoted body only its outermost `$(…)` and backquote substitutions, one per line, because the shell runs them and the bytes cut stored as `heredoc_bytes`, a script in an escaped double-quoted string or a multi-piece quoted word included. Then its content operands are cut (`cmdparse.CutContent`): the message of a `git commit` (the value of `-m`, `--message` or `--trailer`, attached as in `-mMSG`, `-m=MSG`, `--message=MSG` or a cluster `-am MSG`, or the next word) and every operand after the leading flags of an `echo` or `printf` whose standard output goes to a file (`>`, `>>`, `>|`, `&>`, `&>>` to a target outside `/dev/`, its own or that of an enclosing block, subshell, list, loop or branch) or into `tee` are each replaced by the one word `'[cut]'`, and the bytes cut stored as `operand_bytes`. An operand holding literal text keeps its command substitutions after the placeholder (`'[cut]'"$(git rev-parse HEAD)"`), each cut the same way, because the shell runs them; one holding none (`"$X"`, `"$(…)"`) stays as written. `git commit -F FILE` keeps its path, an `echo` to the terminal or into another pipe keeps its words, and a `python3 -c` or `bash -c` script is code and stays whole. Both cuts leave their own output unchanged, so a stored input sanitized again is the same bytes. A command either cutter cannot cut safely, one naming `commit`, `echo` or `printf` that parses as neither bash nor zsh among them, is stored only as `command_bytes`. `content`, `old_string`, `new_string`, `edits`, `new_source` and `prompt` are never stored, for every tool; each, like any other field (free text, an object or array, a label over 4096 bytes), is replaced by its byte length under the same key with a `_bytes` suffix (`content_bytes` in place of `content`).
- `detail`, `background_tasks` and `session_crons` are sanitized JSON: objects and arrays keep their shape; numbers, booleans and null stay; a string value is kept only when its key is one of `id, type, status, source, trigger, level, mode, behavior, destination, notification_type, load_reason, memory_type, command_name, command_source, expansion_type, task_id, tool_name, tool_use_id, model, file_path, trigger_file_path, schedule, cron`, or when it is a label of its event: a `StopFailure` `error` in the shape of an API error kind, `^[a-z][a-z0-9_]{0,63}$`, the gate the transcript path applies to the kind it reads (`APIErrorKind`), so Claude Code's documented `rate_limit, overloaded, authentication_failed, oauth_org_not_allowed, account_on_hold, billing_error, cloud_credential_error, invalid_request, server_error, max_output_tokens, model_not_found, unknown` and any kind it adds later pass while an error in words does not; a `SessionEnd` `reason` one of `clear, resume, logout, prompt_input_exit, bypass_permissions_disabled, other`; every other string becomes `{key}_bytes`, and a string inside an array whose key is not on that list becomes its byte count. The named columns `events.error_type` and `events.reason` keep the same labels; any other value is `label not stored (N bytes)`. `detail` omits the keys that have a column or are common to every event: `session_id, transcript_path, cwd, hook_event_name, prompt_id, agent_id, agent_type, permission_mode, effort`.
- A row stored before a rule existed keeps its old form until `callmeter redact` rewrites it ([The wrapper](#the-wrapper)); every report names how many calls hold such a form, never their text.
- Commit messages given as `git commit` operands, the text an `echo` or `printf` writes to a file, patch lines, command output, heredoc bodies and error text are never stored: an outcome is a count, a sha, a branch name, a runner name or a label. The rest of a command is stored as written, so text it carries in another form stays: a message assigned to a variable before the commit, a commit inside a `bash -c` or `ssh` script string, a word an `echo` prints to the terminal.

### Effort

`effort` on `calls`, `turns` and `events` is the payload's non-empty `effort.level` when present. `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PostToolBatch`, `Stop`, `SubagentStop` and `StopFailure` take it only from the payload; absent effort is NULL. Every other event may take non-empty `CLAUDE_EFFORT` only when its known session model is not haiku-family: `SessionStart` uses its payload model; other events use `SessionModel` (the latest main-chat request wins over `SessionStart`). An unknown model or a model-read error keeps NULL.

### Prune and archive

A report run prunes rows older than 30 days; the hook never prunes. Prune copies and deletes at most 2,000 rows per chunk, releasing the store's write lock between delete chunks so a hook waits on one chunk at a time, within its own busy bound; a write can still fail or time out. `calls`, `requests`, `turns`, `events` and `faults` age by `ts`; `agents` and `agent_turns` by `COALESCE(stopped, started)`; `sessions` by `last_ts`; then orphan `command_parts` go. A `calls` row with NULL `ts` ages by its `requests` row's `ts`; other NULL-time rows stay.

Every row about to go is first archived into `{CALLMETER_HOME}/archive.db`, which holds the same tables minus `calls.input`, `calls.error`, `faults.error` and `events.detail` (`faults.fault_id` included; `user_version` 1, created by the first prune with a row to archive). A prune with no row past the cutoff leaves the store alone and never attaches `archive.db` (`anyToArchive`); an orphan `command_parts` row also counts as a row to archive.

A commit spanning two WAL databases is atomic per file only, so prune runs in two phases. Phase 1 uses short deferred transactions writing only `archive.db`: `INSERT OR REPLACE` for `sessions`, `agents`, `calls` and `requests` archives their current row over the older copy; `INSERT OR IGNORE` for `agent_turns`, `events`, `turns`, `command_parts` and `faults` retains the first copy of each key. Phase 2 uses short `BEGIN IMMEDIATE` transactions writing only `callmeter.db`: no row is deleted unless an identical copy of every archived column is committed in the archive (NULLs compared too). A newer differing `agent_turns`, `events`, `turns`, `command_parts` or `faults` row whose key is already archived stays in the store, even past retention. A reused `fault_id` is subject to the same equality guard. An archive failure stops before phase 2; committed chunks survive any later failure. A crash may leave a row in both files; the next prune refreshes aggregate copies and deletes identical rows, preserving differing facts.

## Parsing a command

A Bash call is often several commands (`F=x; wc -l "$F" && grep -n func "$F"`) and often carries another language inside it (`python3 -c "…"`, `python3 - <<'EOF' … EOF`, `node -e "…"`). The parse happens at report time only (`report.EnsureParsed`), never in the hook, and its result is cached in `command_parts`, keyed by the call. A non-string or absent `command` is skipped, never a parse error. A stored `cwd` or `input` change drops the call's parts for re-parsing at the next report; unchanged merged values leave them intact. Replaced parts and their parse faults land in one transaction, replacing the old parse faults together. No parser is written here; each language uses its established one:

| Language | Parser | Yields |
| --- | --- | --- |
| Shell | `mvdan.cc/sh/v3`, the parser behind `shfmt`, pinned at `v3.14.1`; bash first, and zsh only when bash cannot parse the command (the Bash tool runs the user's `$SHELL`) or a `zsh -c` script, a zsh flag or modifier leaving its word unknown | every simple command with its arguments through pipes, `&&`, `;`, loops, `$(…)`, assignments and redirections |
| Python | Python's own `ast` module, one `python3 -c {embedded script}` process per batch of snippets | calls and string constants: `open(…)`, `Path(…)`, `subprocess` arguments |
| JavaScript (`node -e`) | not parsed: a named gap, counted in every report that counts commands and in `faults` | — |

The Python batch protocol is one process per batch: stdin is a JSON list of `{id, code}`, one entry per snippet found in that batch's Bash calls; stdout is a JSON list of `{id, calls, strings, error}` in the same order. A Python snippet is found in `python3 -c ARG` and in a here-string (the same forms for the bare `python` alias). A `python3 - <<EOF … EOF` or `python3 <<EOF … EOF` heredoc part keeps its program and is `script-body`: the store keeps no quoted heredoc body and of an unquoted one only its command substitutions ([Privacy](#privacy)), so the script is unknown (cause `heredoc body not stored`, or `code holds an unresolved expansion` when substitutions are left). A `-c` script or here-string holding an expansion with no known value (a variable with no single literal value, a `$(…)` or arithmetic substitution) keeps its program and is `unparsed` (cause `code holds an unresolved expansion`): the code the interpreter ran is unknown, so it is never parsed as written. `python3 script.py` attributes the file `script.py` with the action `exec` rather than parsing it.

`command_parts.parse_status` is one of:

| Value | Meaning |
| --- | --- |
| `ok` | parsed cleanly |
| `error` | the parser rejected the snippet; `faults` keeps `part N ({program}): error text not stored ({n} bytes)`, the program `no program parsed` when the part has none, never the message; the only status that makes a parse fault, while `report faults` counts every status as its own `parse` row |
| `unparsed` | a language not parsed (`node -e` and others), a Python `-c` script or here-string holding an unresolved expansion, or a command past a parse bound |
| `script-body` | a part whose program reads its script from a heredoc (`python3 - <<EOF`): the shell part is parsed, the script is not, since the store does not keep it; a gap by design, never a parse fault |
| `python-unavailable` | no `python3` on `PATH`: every Python snippet in the run is marked this way, and `faults` reports the count so the gap is never a silent zero |
| `python-error` | Python ran but its scan failed (exit, malformed output, wrong count or id, missing snippet); the snippets are marked as a gap, never a syntax error |

Calls with `python-error` parts are re-parsed at every report; calls with `python-unavailable` parts are re-parsed only at a report run where `python3` resolves on `PATH` (looked up once per run, as the parser looks it up), and are left unwritten while it does not.

Every parse is bounded, so no command can hold a report run: a command over 65,536 bytes is one `unparsed` part (`command over 65536 bytes`) never handed to the shell parser, a literal `-c` string nested more than 8 levels is one `unparsed` part (`shell -c nested over 8 levels`) in place of its parse, and the globs of one call share 4,096 directory reads and stats and 131,072 directory entries read. Globs and file attribution stats share a per-call IO deadline (`maxGlobTime`, 250 ms from the first file IO), paused across the batch's Python analysis and other calls without renewing a spent deadline; file attribution stats spend no directory-lookup count. Past a glob bound a glob stays as written and its part's error names the bound (`glob */f over 4096 directory lookups, left unexpanded`); each glob read or file attribution stat runs off the parse's goroutine and is abandoned at the deadline, so a directory macOS holds behind a privacy prompt or an automount costs at most the remaining IO budget, never a stall. A held stat leaves the word unattributed with a bound note while the part stays `ok`. An IO panic is re-raised on the waiting parse caller with the IO stack, reaching report recovery; after abandonment it is written once with its stack to stderr and dropped.

From the parsed commands, a file is attributed to a call when an argument, an assigned value or a string constant resolves to a file from the directory the command started in, braces and globs expanded as the shell expands them ([Corpus findings and fixes](#corpus-findings-and-fixes) names when a missing file counts). What a command did with the file (whole read, line range, search, write) comes from a table of the common readers (`cat`, `head`, `tail`, `sed -n`, `grep`, `rg`, `wc`, `open`), each row naming which argument is the range. A command the table does not know attributes its files with the action `unknown`.

One Bash call returns one output: the bytes of a compound command belong to the call, never split across its parts.

A static parse cannot know which branch ran, so every file a part names in a read mode (`read-whole`, `read-range`, `search`) is attributed as read, whether or not its branch ran; the call's bytes are measured at its end either way. What the parse does know is where the part sits: `command_parts.conditional` is 1 for a part inside an `if` branch or the `else` chain (an `elif` condition included), a `case` arm, or on the right-hand side of `&&` or `||`, and 0 otherwise; the first `if` condition and the `case` word run unconditionally. A Bash call's read of a file is certain when any unconditional part of that call names the file, conditional otherwise. A file test (`[`, `test`, `[[ ]]`) reads nothing and attributes no file. The `files` report shows `READS` (every attributed read), then `CERTAIN` and `CONDITIONAL`, so a file that ranks high only through guarded reads (`if [ -f x ]; then cat x; fi`) shows as such, and `EXECS`, the calls that ran the file (`exec`), never a read. A `stat` or `write` attribution is no read; an `unknown` one counts nowhere, and a note names how many there were.

## Reports

`callmeter report {topic} [--since D] [--project P] [--agent-type T] [--session S] [--limit N] [--json]`, each topic a fixed query over the store; flags may follow the topic. Inside Claude Code the same runs as `/callmeter:report {topic} [flags]`. Every report over a store ingests `missed.log`, prunes and archives rows older than 30 days, and fills missing agent metadata and recovers quiet sessions, before it runs; with no store it only counts the `missed.log` lines (below).

Quiet-session recovery (`Store.RecoverQuiet`, `recover.go`) first runs a light metadata fill (`fillAgentMeta`) for existing agents missing parent or type in every session with a transcript path, live or quiet, without hook-age or transcript-mtime gates. It fills only empty fields from `agent-{id}.meta.json` beside the agent transcript. It then reads the transcripts of every session with no hook and no write to its main or sub-agent transcripts for `QuietAfter` (1 h) that holds something to settle: a call with no size at all, a call with no request or a provisional one, a pending request. Such a call stays a candidate until recovery has read every transcript of the session in full and found no `tool_result` for it in any of them (the tool never returned, or an untyped internal agent wrote no transcript) and no request naming it that it could store: one `transcript` fault `call {tool_use_id}: …`, its `tool_use_id` set, then marks it, stamped at the session's last hook, and any later hook reopens it, so a quiet session holding such a call is read once, not at every report. A full read also rebuilds the call row of every transcript `tool_use` at or after `since`, the later of the session's first ts and now minus 30 days (`callmeter.Retention`), that no hook recorded (`RebuiltCall`, `source` `transcript`): Claude Code runs `PreToolUse` only for Bash here, so a session killed mid-call leaves any other call with no row, and a hook can be lost. The row takes its session, sub-agent, tool, request, prompt, the request's ts and its entry's cwd, and its input only through `SanitizeInput`; its request counts it, its result settles it or the call marker above names it. Recovery never recreates pruned calls or requests older than `since`; report retention aliases `callmeter.Retention`. It refreshes `sessions.model` from its latest main-chat request whenever it writes one or resolves a pending main-chat request (`RefreshSessionModel`), and fills an agent row's missing parent `Agent` call and type from the `agent-{id}.meta.json` beside its transcript. A sub-agent's latest turn with no `SubagentStop` whose transcript shows no turn end and whose main transcript shows no qualifying task notice at or after its start (the agent was killed mid-turn), or that wrote no transcript at all, is marked once by a `transcript` fault `agent {agent_id} turn {seq} open: …`, stamped at the session's last hook, and any later hook reopens it; the open agent row is that fault's, as an `end_reason` of `never` is the session's. A session whose latest main-chat prompt has no turn end is a candidate too, until recovery has read its main transcript and found no turn end after the prompt: one `transcript` fault `prompt {prompt_id} UserPromptSubmit {event_id}: …` then marks it, stamped at the session's last hook, and a later prompt (another `event_id`) or any later hook (the fault is older than the session's last hook) makes it a candidate again, so a session that was quiet but still live is read again. So is a session whose latest run has no `SessionEnd`, and so is one holding a sub-agent turn with a stop and no request of that agent since its previous stop: every turn makes a request, so that stop read the transcript before the turn's reply was on disk and no later hook of the agent read it again. So is one holding a main-chat `Stop` with a last assistant message and no request of its `prompt_id` other than a `tool_use` one: the stop's read missed its text reply. It resolves the pending requests, settles each call with no size from its `tool_result` (`SettledCall`), writes each request the transcripts hold at its final usage, and rebuilds the missing `Stop` or `StopFailure` the main transcript shows, as `SessionEnd` does ([Where each fact comes from](#where-each-fact-comes-from)).

`SessionEnd` may not run: Claude Code can end a session, a headless `claude -p` exit among them, without running its `SessionEnd` hooks, and nothing in the session's transcript or hooks records that it did not. Recovery settles that session: once it is quiet, its turn end and its calls settle as above, and when its latest run (from its latest main-chat `SessionStart`, its whole history when it has none) has no main-chat `SessionEnd` event, `sessions.end_reason` becomes `never` (`EndReasonNever`, `MarkNoSessionEnd`), so the absence reads as a fact and never as a NULL. A lost `SessionEnd` is no absence: a `binary` or `terminated` fault whose `error` starts `SessionEnd:` naming the session since that start sets `end_reason` `lost` (`EndReasonLost`, `MarkLostSessionEnd`) while it is NULL, never over a stored reason; one naming no session (a line written before the session field) from 1 s before its last hook to 1 min after (`lostEndWindowMS`) may be another session's, so it leaves `end_reason` NULL, unknown, and the fault names the loss. A session whose transcript is gone is marked too. A session that sits idle at its prompt past the quiet hour reads `never` until its next hook recomputes the column. `CALLMETER_QUIET_AFTER`, a Go duration of zero or more, replaces `QuietAfter` for one report run (`command.QuietAfterEnv`); the e2e sets it to `1ms` to settle the session it just ran, and any other value is a usage error.

Recovery fills missing call and request values; the light metadata pass silently ignores absent or unreadable metadata and counts metadata fills in `Parents`, not `Sessions`; a full quiet-session read still reports unreadable metadata as skipped; agent `total_tokens` and `tool_uses` are the exception, overwritten from the whole transcript at a rebuilt latest stop, as the hook does; a `requests` row it creates carries `source` `transcript`; it stores sizes, flags and labels, never transcript text. A second pass with no newly fillable metadata or transcript evidence leaves settled values unchanged. A sub-agent turn or a main-chat `Stop` still without its request once every transcript of the quiet session was read in full can never be filled (its reply is absent or predates the session's `first_ts`): recovery writes one `transcript` fault naming it (`agent {agent_id} turn stopped {stopped}: …` or `prompt {prompt_id} Stop {event_id}: …`, dated at the turn), and that fault takes it out of the candidates, so no later report reads it again; reconcile expects the fault only when its own transcript parse agrees. An agent's latest turn with no stop whose quiet transcript shows its end gets the `SubagentStop` its hook lost, rebuilt at the earliest end at or after its start (`RecoverAgentStop`, [Where each fact comes from](#where-each-fact-comes-from)); with no such end, the earliest main-transcript task-notification at or after the start closes it instead. A notice is a `user` entry or a `queued_command` attachment with `origin.kind` `task-notification`, a `<task-id>` naming the agent and a non-empty `<status>`, any status value; only id and status are read, never notice text or usage. Both stops use the whole agent transcript's totals (`ReadAgentTotals`), and leave the candidates without an unfillable fault; an agent-transcript end takes priority. Reconcile accepts a rebuilt stop when its own parse shows the agent end or qualifying main-transcript notice at that ts. A transcript that cannot be read is printed to stderr as skipped, and the report goes on with `{n} transcripts could not be read by recovery (first: {label})` in the text and JSON notes; `{label}` is only `permission denied`, `not found` or `unreadable`, never a path or OS error. An absent main transcript follows `markEnd` and is not a skipped-read note.

## Corpus findings and fixes

A one-time study of 30 days of real transcripts (62,005 calls, 4,068 transcripts, three seats) parsed all 37,355 Bash calls, and exposed where attribution was wrong. Each rule below answers one measured defect:

- **Byte share.** A Bash call's bytes are split evenly across the files it attributes: each file is credited `call bytes ÷ files attributed`, so per-file sums add up to the call. One `grep -l` over a 1,445-file glob had credited its whole output to every file.
- **Wrappers.** `command`, `builtin`, `exec`, `env` (its assignments and flags), `timeout` (its duration), `nice`, `nohup`, `time`, `/usr/bin/time`, `sudo` and `xargs` are unwrapped to the program they run, with that program's arguments. A program given as a path is matched by its base name (`/bin/ls` is `ls`); a program path that is a file under the directory its part runs in (after any `cd`) is also attributed with the action `exec`.
- **Inner shells.** The `-c` string of `bash`, `sh` and `zsh` is parsed as shell with the same directory and conditional depth. `ssh`, `docker exec`, `kubectl exec` and any other remote runner are never parsed: their paths live on another machine. A project's own runner that takes a command string (`./run.sh "…"`) is not parsed: a named gap.
- **`cd` within a call.** A literal `cd DIR` moves the directory later parts of the same call resolve against; a `cd` inside `( … )` ends with the subshell; a `cd` to a non-literal target stops relative attribution for the rest of that list.
- **Redirects.** `> f` and `>> f` attribute a `write`, `< f` a `read-whole`; a heredoc (its body cut at capture; the command substitutions an unquoted body keeps parse as parts of their own), `/dev/*` and fd duplications (`2>&1`) attribute nothing.
- **Metadata is not a read.** `ls`, `du`, `stat`, `file`, `find`, `realpath` and `readlink` attribute the action `stat`, which no read count includes; `[`, `test` and `[[ ]]` attribute nothing.
- **Missing files.** A path that a known reader or writer names (a file operand of `cat`, `head`, `tail`, `sed`, `grep`, `rg`, `wc`, a redirect target, a Python `open()`) is attributed even when it does not exist at parse time, with `exists = 0`: history keeps its deleted and scratch files. An unknown program's arguments are attributed only when they exist, so a word that merely looks like a path is never a file. Text that still carries an expansion nobody performed — a `$` or a backquote the shell left inside a Python string, a glob character, braces (`{}` of `xargs -I{}` and `find -exec`, a quoted `{a,b}`), a leading `~` — names a file only when that exact file exists, never as a missing one: 1,315 missing-file rows of the second pass were such text.
- **Tilde and braces.** A word's leading unquoted `~` or `~/` is the home of the user the commands ran as (the report's home); `~user`, `~+` and `~-` attribute nothing. A Python string starting `~/` is expanded the same way, since it is `expanduser`'s input. An argument's `{a,b}` is brace-expanded as bash does before any glob (mvdan's `syntax.SplitBraces` and `expand.Braces`), so `wc -l internal/{a,b}/x.go` names two files; a sequence (`{1..9}`) or a product over 64 words stays one literal word. Before this, 756 rows were a `~` joined to the call's directory as a literal folder.
- **The directory a command starts in.** `PostToolUse`'s `cwd` is where the command left the shell, and the parser replays the command's own `cd` from the stored directory, so the hook stores `PreToolUse`'s ([The hooks](#the-hooks)). The transcript's `cwd` is the starting directory in 16 of the 23 calls of the corpus that open with a relative `cd`; the other 7 are calls sent in parallel. The Bash tool's directory persists from one call to the next, even between calls of one parallel batch, which is why only `PreToolUse` is trusted.
- **A parser fix reaches stored calls.** Every part records the `cmdparse.Version` that produced it, and a report parses again every call whose parts carry an older one, replacing its parts and its parse faults; without it a fix would leave 30 days of stale attributions.
- **Parse bounds.** `FuzzParse` stalled at 0 execs/s on globs over the filesystem root (`/*/*/*/*/a`, over 1 s under ten fuzz workers; `/*/*/*/*/*/*/a` takes seconds alone); the cause was ours, `filepath.Glob` reading every directory the pattern reaches, not `mvdan.cc/sh`, and the fix is the shared glob lookup bound beside the size and nesting bounds ([Parsing a command](#parsing-a-command)); a lookup count still let one blocked read hold the parse (`/*/*/*/*/*/*/a` over 1 s alone on a host whose walk reached a directory macOS guards), so the walk also carries an entry bound and a 250 ms deadline it waits on in place of the read; 180 s of fuzzing after it ran at 18,000 to 180,000 execs/s with no stall and no failure.
- **Shapes.** `echo`, `printf`, `true` and `:` with literal-only arguments are trivial in a command shape, like `cd` and `export`, so a separator `echo ---` does not split `sed ; grep` into a new shape.

### Test corpora

Unit tests alone passed while this corpus failed, so two tests made of real data guard the parser and the hook:

1. **Real commands.** A table-driven test of Bash commands taken from the one-time study of real transcripts (nested quoting, heredocs, `cd` chains, wrappers, globs, redirects, inner `bash -c`, Python heredocs, loops, arrays), each with its expected parts, attributions, actions and `conditional` flags. Paths are rewritten to `/tmp/demo-proj/…`; the case keeps the command's structure verbatim. The corpus lives in `internal/callmeter/cmdparse/testdata/commands-corpus.json`; a case whose parse differs from the spec carries `known_defect` and is skipped by name until it matches.
2. **Captured hook payloads.** The payloads captured from headless sessions ([Evidence](#evidence)), in `internal/hookentry/testdata/callmeter/` with their transcripts in its `demo-home/`, are fed through the hook into a real store; the test then runs `report.EnsureParsed` and the reports over what the hook recorded.

Fixtures come only from sessions over invented toy projects, never from a project holding client data, and every fixture file passes `scripts/leak-check.sh` before it is committed: every path rewritten to `/tmp/demo-proj/…` and `/tmp/demo-home/…`, no username, no email.

## Build decisions

Decided while building, one line each, file named:

- Store (`store.go`, `write.go`): prune keeps rows with no timestamp and ages agents by `COALESCE(stopped, started)`, and with no row past the cutoff attaches no `archive.db` (`anyToArchive`); `ResolveRequest` merges a provisional row into the message row (stored values win, NULLs filled, `calls` summed, the earlier `ts` kept); `calls.error` keeps only the sanitized label or exit code, never truncated error text; an open writes nothing when the schema version is current, creates the schema under `BEGIN IMMEDIATE`, and retries a busy open until `BusyTimeout`.
- Sanitized input (`sanitize.go`): the dropped fields become `{name}_bytes` for every tool; a field off the kept and label lists (`description`, `query` and `target` among them), or a label over 4096 bytes, becomes `{name}_bytes`; an `mcp__` tool keeps no string, every string field becoming `{name}_bytes`, its numbers, booleans and null kept; a `url` label is cut before its first `?` or `#` and loses the userinfo before its host (`cutURL`); a `Bash` or `Monitor` command keeps its text with heredoc bodies cut (`cmdparse.RedactHeredocs`), an unquoted body cut down to its outermost command substitutions, one per line, a heredoc inside one cut the same way (`keptSubsts`), then each commit message and each operand of an `echo` or `printf` writing to a file or into `tee` replaced by `'[cut]'` under `operand_bytes` (`cmdparse.CutContent`), a command already cut coming back the same bytes (`TestCutContentOverCorpus` over every corpus command), else only `command_bytes`, as for a body whose backquoted substitution may hold a heredoc; `SanitizeError` keeps `Exit code N` or an outcome label, else `error text not stored`; input that is not a JSON object is an error.
- The hook (`hookentry/callmeter.go`): `bytes_real` is NULL for successful Edit, Write and Agent, else `callmeter.RealBytes` of the response, the first of `persistedOutputSize`, stdout, `file.content`, `content`, the response JSON's length, which a rebuilt call's transcript `toolUseResult` is measured by too; a batch spanning several messages writes one request per message; `Stop` resolves pending requests, settles unfinished calls from the transcript (their real size included: a failed result's text, else `callmeter.RealBytes` of its `toolUseResult`) and writes every request its session's transcripts hold, `SubagentStop` writes every request of its agent's transcript, each only over a `requests` row of the same session (or none yet) and agent (`Tx.SettleRequest`), so a fork's copy of its parent's history never overwrites the parent's tokens, and `SessionEnd` does the same as `Stop` within a 1.2 s budget after committing its own rows, waiting per transcript up to 400 ms (`unfinishedSettle`) for the `tool_result` of a call still running and writing a `transcript` fault for each call still without one, then rebuilding a lost `Stop` or `StopFailure` from the main transcript (`recoverTurnEnd`); a payload with no `session_id`, and a stat failure other than not-exist, are `payload` faults; the store's home resolves through `paths.Home`, so `CALLMETER_HOME` jails it; `SubagentStop` overwrites `total_tokens` and `tool_uses` only at the latest stop from the whole transcript (a message id's usage counted once, distinct `tool_use` blocks), while its model only fills; the `Agent` result writes neither total; a store open that fails names a batch's call ids.
- Delivered bytes (`callmeter.DeliveredBytes`): only `text` blocks count; a shape it cannot measure is an error, never a guess.
- File columns (`FileColumnsFromInput`, `FileColumnsFromResult`), used by the hook: `Read`, `Write`, `Edit`, `MultiEdit`, `NotebookEdit`; a relative path joins `cwd`; the Read input's `offset`/`limit` are overridden field by field by the result's `startLine`/`numLines`/`totalLines`; `type: create` with a null `originalFile` is 0; a file tool with no path is a fault.
- Parser (`cmdparse`): a bare assignment makes no part and its literal value is substituted into later uses; ranges are `head` → `1,N`, `tail` → `-N` or `K,$`, `sed` → `A,B`; `sed -i` is a write; a Python snippet's id is `{callID}#{seq}`; `node file.js` is a plain shell part, only `-e`/`--eval`/`-p`/`--print` are unparsed; a file operand of `cat`, `head`, `tail`, `sed`, `grep`/`egrep`/`fgrep`/`rg`, `wc`, a redirect target and a Python `open()`/`Path(…)` read or write is attributed when missing, `Exists = false`, unless its text is a placeholder (`placeholder`: `$`, a backquote, a glob character, `{…}`, a leading `~`); `-`, a directory, a glob that matched nothing and a reader's operands under `xargs` never are; a leading unquoted `~`/`~/` is `Call.Home` (the report passes the home `paths` resolves), and no home, `~user`, `~+` or `~-` leave the word unknown; an argument word is brace-expanded first (`braces`, over `syntax.SplitBraces` and `expand.Braces`, which `syntax.Walk` cannot visit, hence `braceBound`), a sequence or a product over 64 kept literal; a wrapper is unwrapped in `wrappers.go` and the part records the program it runs with that program's arguments; `command -v`/`-V` and a wrapper naming no program stay the wrapper's part and attribute no file; a program path resolves against the directory its part runs in after any `cd` and is `exec` only when it is a regular file under that directory; `bash`/`sh`/`zsh FILE` attributes FILE as `exec` and the words before and after it as `unknown`, while `-n` and `-s` make no `exec` and leave every operand `unknown`; `find` stats only its starting points, never a word of its expression; a Python `-c` script or here-string holding an expansion with no single literal value, a `$(…)` or an arithmetic substitution is one `unparsed` part (`code holds an unresolved expansion`) that keeps its program, never an error part; a literal `bash`/`sh`/`zsh` `-c` string (flag clusters `-lc`, `-ec` included) keeps the shell part (its program file and redirections) and appends the string's parts after it at the same conditional depth, starting in the current directory, in a child scope whose `cd` and variables end with it; a non-literal string is an ordinary part, one that fails to parse is one error part; `cd` moves the directory statically, even in a branch, and `( … )`, `$(…)` and each side of a pipe restore it; after a `cd` the parse cannot know, relative paths attribute nothing until a literal absolute `cd`; a Python part resolves its strings in the directory it ran in; `NAME=(…)` with literal elements expands through `${NAME[@]}`, `${NAME[*]}` (every element), `${NAME[N]}` and `$NAME` (the first); a `for` loop's items and an array's elements expand as any unquoted word does, and a value built from a glob that matched nothing is never a missing file; an unquoted `\X` is `X` and a backslash-newline is removed, so an escaped glob character stays literal; a backslash inside double quotes escapes only `$`, a backquote, `"`, `\` and a newline; `ssh`, `mosh` and the `exec`/`run` verbs of `docker`, `podman`, `kubectl` and `oc` attribute no argument; `cmdparse.Version` is raised with every change to what a command parses to, and `report.EnsureParsed` parses again every call whose parts carry another version (`Tx.ReplaceCommandParts` replaces the parts and the call's parse faults together); word evaluation lives in `words.go`, the walk in `cmdparse.go`.
- Reports (`report/*.go`): a Bash call's bytes go to a file only when the call reads that one file (a missing file included) and has no `exec` or `unknown` attribution, else to no file, counted in a note (`files.go`); `echo`, `printf`, `true` and `:` are trivial in a shape only when the part credits no file and no argument's stored text holds `$`, a backquote, `<(` or `>(` (one rule, `trivialPart`, shared by `commands` and `sequences`); `files` shows SIZE `gone` when the latest call naming a file found it missing, `-` when no size was ever seen; a Read is ranged when `read_start > 1` or `read_lines < read_total_lines`; the 20,000–30,000 band is measured on `bytes_real`; p50 and p95 are nearest-rank; `context` lists growth only and names each jump by the previous request's calls; `sequences` counts overlapping windows, drops a shorter run occurring exactly as often as a longer run containing it, and ranks by occurrences × bytes.
- Found live in the first minutes after install: a failed Bash call's size is its error text, the hook's `PostToolUseFailure` `error` (the transcript's `toolUseResult` is the same text behind `Error: `); Claude Code stops its own internal agents (every `/compact` among them) with a `SubagentStop` that has no `agent_type`, no `SubagentStart` and no transcript on disk, and the hook records no agent for those (`untypedAgentMissingTranscript`; 16 false transcript faults before), while a typed agent missing its transcript stays a fault; the same exemption covers `PreToolUse` and `PostToolBatch` for one of these agents, so neither reads the missing file nor writes a pending request; a call still running has only its `PreToolUse` row until its result lands; a headless `claude -p` cancels running async hooks at exit ("Hook cancelled"), so its last calls can lose their `PostToolUse` and keep only their `PreToolUse` row.
- Pending requests: every `PostToolBatch` also retries the pending requests of its own chat or sub-agent (`resolvePending`), as do `SubagentStop`, `Stop` and `SessionEnd`, so a request that missed the disk at its batch resolves at the next one, not at a `Stop` an hour away (live: 11 pending on running sub-agents, every id already on disk).
- Agent totals (`settledAgentTotals`, `recordAgent`): 31 of 33 live agents were summed without their final message, because `SubagentStop` fires before that line is flushed; a waiting orchestrator stored 10 of its 86 tool uses and a `started` after its `stopped`, because each turn restarts and re-stops it. The stop waits for the final message of its own turn, the one answering its `prompt_id`, so a woken agent's earlier `end_turn` never ends the wait; the latest stop's sums win, and `started` keeps the first start. A compaction's stop skips the wait.
- Request lookup (`callmeter.FindRequests`): reads the transcript's last MB first and widens fourfold only while a wanted id is missing, reads each window to its end, since a message's final entry follows the entry naming the id, and decodes a line only when it names a wanted id or a message already found; a request takes its model, stop reason and usage from its message's last entry; a malformed line naming one is an error at its byte offset, a malformed line naming none is never read. Measured on a 40 MB transcript: `PostToolBatch` 111 ms → 10 ms at the median. Every event's hook runs about 12 ms (process start, store open, one write) on a 63,000-call store, all of it async.
- The start directory (`hookentry/callmeter.go`, `recordStartCwd`): `PreToolUse` upserts `cwd` with `Overwrite` and `tool` with `FillEmpty`, and every hook of a call writes `ts` with `KeepMin`, so the call keeps its earliest start, including the result hook's duration estimate and a call that never finishes still ages out; `PostToolUse` upserts its result columns with `Overwrite` and `cwd` and `prompt_id` with `FillEmpty`; `PostToolBatch` writes `bytes_delivered`, `request_id` and the issuing `prompt_id` with `Overwrite`, and `ts`, `tool`, the sanitized `input`, the file columns and a refusal's `failed`, `error` and `bytes_real` with `FillEmpty`; a `PreToolUse` payload without `tool_use_id` or `cwd` is a `payload` fault.
- One write batch, one transaction: every write batch of one hook run (the call or request, its event, turn, agent turns and session refresh) goes in one batch, and a `UserPromptSubmit` whose prompt starts with `<task-notification>` carries `task_notification` in its `detail`, since Claude Code fires that event for its own background-task notices, which are not user turns. Quiet recovery separately reads qualifying main-transcript task notices from `user` entries or `queued_command` attachments as completion evidence for an agent with no own turn end; no notice hook is required.

## What it does not do

- It changes nothing a model sees: no hook output, no added context, no blocked call.
- No account join: a call is tied to the seat it ran under (`seat_dir`), never to an account name.
- No guard-fire rows and no receiver id for chat-to-chat messages.
- No Codex or OpenCode recording; that belongs to a later pfm flight.
- No `node -e` parsing: an unparsed, counted gap.
- No Windows: the wrapper is POSIX sh and the binaries are built for darwin and linux only.
- No prompt text, message text, file content, patch lines, commit messages or command output in the store, beyond what a Bash command's own text carries past the cuts of [Privacy](#privacy).
- No record of a hook run killed by SIGKILL, or by a signal that lands before the binary's handler or the wrapper's trap is installed.
- No `missed.log` line for a cached binary run by `exec` that cannot start or dies outside its own signal handler: the wrapper is gone once it hands off.
- No guard against a lock holder suspended past 120 s losing its lock: the second download verifies against `SHA256SUMS` and lands by atomic rename like the first.
- No CI leak scan on fork and Dependabot pull requests until a Dependabot secret is added: they get no secret, so the leak step has zero terms and fails closed.
- No second event for byte-identical deliveries within 1 s of each other: they stay one `turns` or `events` row.

## Evidence

A capture hook, loaded only into headless sessions in a scratch directory over invented toy projects, logged every raw payload.

Claude Code 2.1.280, loaded through `--settings`:

- A scripted sonnet run read one file eight ways (Read whole and ranged, `cat`, `head | tail`, `sed -n`, `python3 -c "open(…)"`, a compound with a variable, a loop), then wrote, edited, appended through Bash, printed a large output, failed a command and spawned a haiku sub-agent. Every call that ran produced `PostToolUse` or `PostToolUseFailure`; the sub-agent's calls carried its `agent_id`.
- `seq` at 5,000 / 6,000 / 6,500 / 7,000 / 9,000 lines: delivered whole at 23,892 and 28,892 chars, as a 2,775-byte preview at 31,393 and above.
- `PostToolBatch`: three parallel calls came as one batch of three, a single call as a batch of one; its `tool_response` for `seq 1 7000` was the `<persisted-output>` preview.
- `updatedToolOutput`: with a test-output filter wired on `PostToolUse`, a fake `pytest` printing 302 lines reached the model as 200 lines, and `PostToolBatch` carried those 200.
- Transcript timing, 11 calls across a chat and a sub-agent: the call's request was absent at `PreToolUse` in 11 of 11, present at `PostToolUse` in 11 of 11 in one run and 0 of 5 in another, and present 0.5 s later in 11 of 11.
- A natural opus run in bypass mode, where the harness withholds the Grep and Glob tools, searched with `grep -rn` through Bash in 4 of its 6 calls and read with ranged `Read` in 2.

Claude Code 2.1.286, as a plugin: a per-event verification capture (every hook event registered, 12 headless sessions on haiku: tools, permissions, a sub-agent, a slash-command skill, a bad model, a one-token output cap, `--init-only`, a resumed `/compact`, `--worktree`) and a gymnastics capture (four sonnet sessions in bypass mode: wide parallel batches, persisted output, background and nested sub-agents woken by `SendMessage`, two `/compact` cycles over one session id, paths with spaces, Unicode and symlinks, deleted files, an image, a Bash timeout, a background Bash). What they showed:

- Plugin hooks fire under `claude -p --plugin-dir`; `CLAUDE_PLUGIN_ROOT` is the `--plugin-dir` path as given, and `CLAUDE_PLUGIN_DATA` is `{CLAUDE_CONFIG_DIR}/plugins/data/{plugin}-{marketplace}` (per seat, hence [Where the store lives](#where-the-store-lives)). `TZ` is unset in every hook process.
- `effort` is in tool payloads on sonnet and absent on haiku; `CLAUDE_EFFORT` is exported to every hook, hence the env fallback of [Effort](#effort).
- `prompt_id` is absent on `SessionStart` startup and resume and on `Setup`, present on nearly every other event.
- `SessionStart` carries `model` only for source `compact`; a resume adds `seconds_since_last_response`, `context_tokens` and cache fields.
- `SessionEnd` `reason` is `other` on every `-p` exit, and a resume cycle is `SessionStart` (`resume`) … `SessionEnd`. `SessionEnd` may not run: a process can exit with no `SessionEnd` hook started, its debug log showing no `SessionEnd:` hook line; recovery settles it ([Reports](#reports)).
- `PostToolBatch.tool_calls[].tool_response` is a string; `PostToolUse.tool_response` is an object whose shape varies by tool.
- A persisted output's `PostToolUse` `stdout` is cut at 30,000 chars beside `persistedOutputPath` and `persistedOutputSize`; the `<persisted-output>` wrapper appears only in `PostToolBatch`.
- Every `/compact` fires a `SubagentStop` with empty `agent_type`, no `SubagentStart`, and an agent transcript path missing on disk.
- Harness `<task-notification>` prompts fire `UserPromptSubmit`; `/compact` itself does not. Agent completion evidence can also be a main-transcript `queued_command` attachment with `origin.kind` `task-notification`, without a `UserPromptSubmit` notice; recovery reads only task-id and non-empty status.
- The Bash cwd persists across calls, even inside one parallel batch: a `cd sub && …` in one call made two sibling calls of the same batch fail on relative paths.
- A background sub-agent woken by `SendMessage` starts and stops twice; a nested agent's `SubagentStop` arrives after its parent's, and the parent's `Agent` `PostToolUse` after the parent's own stop. The nested-agent replay also recovers a lost stop at its task notice from the agent's own totals, with no unfillable-turn fault.
- `StopFailure` replaces `Stop` on an API error (`model_not_found`, `max_output_tokens`) and is the one non-tool event seen carrying `effort`.
- `WorktreeCreate` and `WorktreeRemove` never fired: in a git repository Claude Code created the worktree natively. A `WorktreeCreate` hook can replace creation, so neither is registered.
- `MessageDisplay` fires per streamed chunk under `-p` and is not registered.
- Never triggered under `-p` and not registered or not relied on: `Notification`, `PermissionDenied` (registered, recorded when they fire), `CwdChanged`, `DirectoryAdded`, `ConfigChange`, `FileChanged`, `TeammateIdle`, `PreModelSwitch`, `PostModelSwitch`, `Elicitation`, `ElicitationResult`.

## Open items

- Retention: **Decided.** 30 days. Every report prunes rows older than 30 days, archiving them first; the hook never prunes.
- The store's location: **Decided.** `CALLMETER_HOME`, one store per machine across seats ([Where the store lives](#where-the-store-lives)).
- `node -e` parsing: **Decided.** It stays unparsed in this version: a named gap, counted in every report that counts commands and in `faults`.
- `BASH_MAX_OUTPUT_LENGTH`: **Decided.** Unchanged.
- `Notification` and `PermissionDenied` payloads: open. Both are registered and stored with sanitized `detail`, but neither fired under `-p` in any capture. A live auto-mode denial carried `tool_name` and `tool_use_id`, as `PermissionRequest` carries `tool_name`, so `PermissionDenied` fills `events.tool_name` and keeps `tool_use_id` in `detail`; no other named column relies on either shape.
